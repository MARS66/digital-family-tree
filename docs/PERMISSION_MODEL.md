# 用户角色、权限与隐私模型

## 1. 身份原则

`User` 表示登录账号，`Person` 表示某个 Family 中的谱系人物，两者永不合并成同一实体。关联通过 `PersonClaim`：

- 一个 User 可加入多个 Family。
- 一个 User 可在不同 Family 认领不同 Person。
- 同一 Family 中默认一个 User 只有一个有效的本人认领。
- 同一 Person 默认只有一个已批准的主要本人认领；代管、监护等另建授权，不伪装为本人。

## 2. 角色

| 角色       | 范围          | 主要能力                                               |
| ---------- | ------------- | ------------------------------------------------------ |
| 创建者     | Family        | 初始最高管理权、移交所有权；不能绕过审计               |
| 家族管理员 | Family        | 成员、分支、审核、合并、导入、隐私策略管理             |
| 分支管理员 | Branch        | 管理本分支邀请、成员与贡献；跨分支关键变更需家族管理员 |
| 普通成员   | Family        | 按范围查看、认领、提交贡献、管理本人隐私               |
| 访客       | 邀请/授权范围 | 只读公开或明确授权内容，不默认成为成员                 |

创建者是特殊的家族管理员，但删除家族、所有权移交等高风险操作需二次确认和审计。

## 3. 权限矩阵（V1）

| 操作               |          创建者/家族管理员 |       分支管理员 |           普通成员 |   访客 |
| ------------------ | -------------------------: | ---------------: | -----------------: | -----: |
| 查看家族基本资料   |                         是 |               是 |                 是 | 授权时 |
| 查看人物非敏感字段 |                     按隐私 |           按隐私 |             按隐私 | 最小化 |
| 提交人物/关系修改  |                         是 |           本分支 |       允许贡献范围 |     否 |
| 直接改正式数据     | 仅低风险配置；事实仍走修订 |               否 |                 否 |     否 |
| 审核贡献           |                         是 |   本分支非冲突项 |                 否 |     否 |
| 创建/撤销邀请      |                         是 |           本分支 | 人物求助型（受限） |     否 |
| 管理成员角色       |                         是 |   本分支普通成员 |                 否 |     否 |
| 合并人物           |         是（双人复核建议） |             提议 |               提议 |     否 |
| 批量导入           |                         是 | 本分支（需审核） |                 否 |     否 |
| 查看审计           |                         是 |           本分支 |           本人相关 |     否 |

所有权限由后端计算：角色权限 ∩ 资源范围 ∩ 字段隐私 ∩ 数据状态。前端隐藏仅改善体验。

## 4. 字段级可见性

建议的可见范围枚举：

- `SELF`：仅本人有效认领账号。
- `DIRECT_RELATIVES`：父母、子女、伴侣。
- `WITHIN_3_DEGREES`：经允许的三度亲属范围，按图遍历且限制关系类型。
- `BRANCH`：同一分支成员。
- `FAMILY`：全家族成员。
- `ADMINS`：对应范围管理员。
- `PUBLIC_LINK`：明确授权的访客链接；V1 谨慎启用。

默认建议：

| 字段                 | 在世人物默认                     | 已故人物默认        |
| -------------------- | -------------------------------- | ------------------- |
| 姓名/称谓            | Family                           | Family              |
| 性别、关系           | Family                           | Family              |
| 完整生日             | Self + Direct relatives + Admins | Family（可配置）    |
| 出生年份             | Branch 或 Family                 | Family              |
| 电话、微信、详细地址 | Self；明确授权 Direct relatives  | 不公开/无意义时清除 |
| 照片                 | Branch                           | Family              |
| 生平、事件、来源附件 | 按记录设置                       | 按记录设置          |

敏感字段存储应加密或令牌化，日志与分析事件不得包含明文。访问附件使用短时签名 URL。

## 5. 编辑与本人权利

- 本人可建议修改自己的资料并收紧其敏感字段可见范围。
- 谱系关系属于共享事实，不能由单方无痕删除；必须提交变更并审核。
- 本人隐藏敏感字段不等于从谱中删除 Person。
- 对错误认领提供申诉、撤销和管理员处置；处置全程留痕。

## 6. 审核与可信机制

### 三层数据

1. **正式层**：当前已批准并可用于家谱视图的事实。
2. **待审核层**：贡献中的候选增删改，不覆盖正式层。
3. **历史层**：每次批准、合并、撤销前后的不可变修订记录。

### 来源等级（提示，不等同于真伪裁决）

- 本人确认。
- 近亲确认/口述。
- 族谱、证件、碑记、档案等文献。
- 导入文件。
- AI/OCR 解析候选。
- 未注明来源。

AI/OCR 只能生成候选人物、字段、关系及置信度和原文定位，不能直接写正式层。最终确认必须记录操作者、时间和依据。

## 7. 风险操作

人物合并、批量批准、删除家族、所有权移交、公开范围扩大需二次确认。合并与批量操作生成独立审计事件；V1 建议人物合并由家族管理员执行并要求明确预览影响。
