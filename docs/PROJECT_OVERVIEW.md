# 项目总览

## 产品愿景

让每个家族都能建立一份可信、可传承、可持续共建的数字家族档案；让散落在个人记忆、微信群、纸谱和文件里的家族信息，转化为有来源、有权限、有版本的结构化数据。

## 产品定位

产品不是单纯“画家谱”的工具，而是三位一体的平台：

1. **家族数字档案**：保存人物、事件、照片、来源与修订历史。
2. **关系网络**：以人物和亲属/伴侣关系为结构化本体，支持多种视图。
3. **协作共建平台**：通过邀请、认领、家庭补录、审核和任务把录谱工作分散给各分支。

数据库中的人物与关系是本体；“家谱树”只是按视角、代际和权限生成的 View。界面不得成为数据模型的反向约束。

## 核心价值

- 对家族：把零散、易失的信息沉淀为可追溯的共同资产。
- 对创建者/管理员：以审核、查重和版本机制降低千人补谱的组织成本。
- 对普通成员：从“填写整本谱”降为“认领自己并补全一个家庭单元”。
- 对老人：通过亲友代录、极简步骤和来源说明降低数字门槛。
- 对后代：获得可检索、可验证、可扩展的家族历史。

## 目标用户

- 发起修谱的创建者、族长、宗亲组织者。
- 熟悉某一支系的分支负责人。
- 通过微信群进入的普通家族成员。
- 掌握口述历史但不擅长数字工具的老人。
- 只被授权查看部分内容的访客。

## 产品原则

1. **事实优先**：已确认事实、待审核候选、历史版本明确分层。
2. **账号与人物分离**：`User` 是登录身份，`Person` 是谱中人物；一个用户可在多个家族认领不同人物。
3. **最小贡献单位**：以家庭单元补录，避免要求普通成员理解复杂谱系。
4. **来源可追溯**：关键事实应能关联资料来源与提交者。
5. **先候选后入库**：导入、OCR、AI 和普通成员提交都先进入候选/审核流程。
6. **隐私默认收敛**：敏感字段最小可见；查看权不自动带来编辑权。
7. **关系规范化**：存储必要的直接关系，兄弟姐妹等关系由系统推导。
8. **渐进扩张**：先支持几十至千人协作补谱，不在 V1 追求超大画布或全功能族谱出版。
9. **移动优先**：适应微信分享、二维码、碎片化填写与低认知负担。
10. **所有关键变更可撤销**：软删除、乐观锁、修订记录和合并记录不可缺失。

## 成功定义

一个新家族能够从零建立主干，并通过多个分支邀请持续增长；成员能认领自己、补全父母/伴侣/子女并提交；管理员能发现重复与冲突、审核后使数据生效；任何关键事实都能回答“谁在何时依据什么改了什么”。
