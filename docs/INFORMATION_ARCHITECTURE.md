# 信息架构与微信小程序页面规格

## 1. 顶层结构

V1 底部导航固定为：

- **家族**：当前家族、局部家谱、人物与分支。
- **共建**：我的补谱任务、贡献草稿、待审核/审核队列、邀请。
- **我的**：我的认领、加入的家族、隐私与账号设置。

全局上下文包含当前 Family；用户加入多个家族时可切换。邀请落地页可在登录前展示最小公开信息，但敏感内容必须登录并授权后读取。

## 3. 管理页（从相关页面进入，不新增 Tab）

- 家族设置：资料、默认隐私、角色、所有权移交。
- 成员管理：成员、状态、角色调整。
- 分支管理：创建、锚点、管理员。
- 数据质量：重复候选、冲突、孤立人物、缺来源。
- 人物合并预览：字段、关系、认领与历史影响，确认后执行。

## 4. 通用状态规范

- `loading`：骨架屏，避免把旧家族数据短暂显示到新家族。
- `empty`：说明原因 + 一个主行动，不只显示空白。
- `error`：可重试；显示用户可理解的错误和追踪编号。
- `forbidden`：说明缺少的权限并提供返回，不暴露资源细节。
- `conflict`：展示服务器当前版本与用户草稿，允许刷新后重新应用。
- `pending`：明确“尚未进入正式家谱”。
- `merged`：跳转保留人物并展示合并说明。
- `deleted`：对普通用户显示不可用；管理员可见审计入口。

## 5. 展示模型

V1 不加载完整家族画布：

- 以我为中心：焦点 + 父母 + 伴侣 + 子女，按需再展开一层。
- 祖先简图：默认 3 代，逐层加载。
- 后代简图：默认 2–3 代，可折叠分支。

服务端先按隐私过滤节点和字段，再返回 View DTO。隐藏人物可用“受保护的亲属”占位保持结构，但不得泄露姓名、生日等。后续再扩展完整世系、时间轴、迁徙地图、人物册、家族志和 PDF。
