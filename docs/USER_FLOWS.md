# 用户流程与从 0 到 1000 人补谱增长

## 1. 核心对象与增长单位

- **主干骨架**：先录入少量确定的祖辈、关键后代和分支连接点，不追求一次完整。
- **家庭单元**：围绕一个焦点人物补父母、伴侣、子女，是普通成员最小任务。
- **递归分支**：每位已认领成员再邀请自己熟悉的亲属，形成分散录入网络。

## 2. 核心闭环

1. 创建者创建家族，设定名称与基本说明。
2. 创建首个人物并认领，录入 2–3 代主干。
3. 按已知支系创建 Branch，把分支负责人设为管理员或发出分支邀请。
4. 分享家族/分支/人物二维码到对应微信群或私聊。
5. 成员打开后看到邀请上下文、数据用途和隐私说明。
6. 成员搜索/选择候选 Person；找不到时申请新增，不直接制造正式重复。
7. 提交认领；通过后获得与角色、亲缘范围匹配的查看/贡献能力。
8. 系统发起家庭单元任务，成员填写“我知道的”，允许未知人物占位。
9. 成员附来源、选择“本人确认/亲属口述/旧谱/其他”，提交贡献。
10. 管理员处理重复和冲突，批准、驳回或要求修改。
11. 批准后数据正式生效，局部家谱扩张，并建议邀请下一位亲属。

## 3. 0→1000 人运营分段

### 0→30：可信主干

- 创建者录入最确定的 2–4 代与主要分支锚点。
- 每条关键关系尽量附“谁确认/来自何处”。
- 不确定姓名可创建显式未知占位，如“张某之父（姓名待考）”，不得伪造姓名。
- 成功门槛：主干连通、无循环、每个主要分支至少一个邀请锚点。

### 30→150：分支接力

- 每个分支指定一名熟悉情况的负责人。
- 使用分支二维码进入正确上下文，减少选错人物。
- 每位负责人优先补直系家庭，再邀请兄弟姐妹或堂亲接龙。
- 系统展示分支完成度：已认领人数、缺父母/伴侣/子女人物数、待审核数。

### 150→500：任务化共建

- 自动生成补谱任务：认领待确认、缺失父母、缺少来源、疑似重复、关系冲突。
- “向亲戚求助”生成只含必要上下文的分享卡；被求助者无需先理解全谱。
- 管理员按分支分流审核，避免单点瓶颈。
- 对高争议数据保持候选状态，不为追求完成度强行定论。

### 500→1000：批量与质量治理

- Excel 导入用于录入既有名册或旧谱索引，先进入暂存区。
- 通过姓名、性别、出生信息、父母/伴侣、分支等产生重复候选。
- 分批确认，优先解决连接主干的高价值记录。
- 定期查看孤立人物、无来源关键关系、长期待审核、合并频繁区域。

## 4. 邀请类型

| 类型     | 上下文          | 典型用途         | 默认落点          |
| -------- | --------------- | ---------------- | ----------------- |
| 家族邀请 | Family          | 广泛招募         | 家族介绍/搜索认领 |
| 分支邀请 | Family + Branch | 分支微信群接龙   | 分支页/候选人物   |
| 人物邀请 | Family + Person | 请本人或近亲认领 | 人物摘要/认领页   |

邀请令牌仅保存哈希；支持有效期、次数限制、撤销。二维码中不嵌入敏感资料。

## 5. 特殊流程

### 未知人物占位

占位必须有 `is_placeholder=true`、上下文标签和创建原因。它可承载关系但不能被正常认领；查明身份后通过“补全/合并”转为真实人物，历史保留。

### 找不到本人

用户提交“新增候选人物”，系统先查重；若相似，要求选择现有人物或提交差异说明。管理员确认后创建或合并。

### 老人参与

允许亲属代录并标记“口述者”和“录入者”；表单一次只问一个家庭单元；支持暂存、稍后继续和大字号。代录不等同于代认领。

### 接龙补谱

完成家庭单元后，系统列出 1–3 个最合适的下一联系人建议。分享卡只暴露必要称谓、分支和邀请说明。

### 争议关系

冲突事实不覆盖正式数据；新主张作为候选并列，进入专门审核。管理员不能删除不同意见的提交历史。
